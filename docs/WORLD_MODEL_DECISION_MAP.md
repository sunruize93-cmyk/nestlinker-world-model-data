## #1: 我们到底在建什么？

Blocked by: none  
Type: Discuss

### Question

是实时房源平台、首尔数字孪生，还是外国租客的决策演练系统？

### Answer

已决定：建立 **Foreign Renter Decision World Model**。它是一个可校准的概率决策模型，不是对首尔房屋的物理复制，也不宣称拥有实时库存。对外价值是“来韩前先练一遍，知道哪里可能失败、下一步去哪里核验”。

## #3: 目标函数如何定义？

Blocked by: #2  
Type: Discuss

### Question

模型应该优化成交率、停留时间、价格，还是减少可避免损失？

### Answer

已决定（2026-09-03）：采用 **安全优先的分层目标函数**，优先让外国租客更少承担押金及合同风险。

1. **安全门槛**：任何候选策略必须满足现金预算、最低住房连续性，以及不可跳过的押金/合同 Real-World Checkpoint；模型证据不足时应输出“暂停、核验或使用临时住房”，而不是硬推成交。
2. **首要目标**：在安全可行策略中，最小化押金损失和合同伤害的尾部风险。押金风险与合同风险分别受限，不能让一个维度的改善掩盖另一个维度的恶化。
3. **次要目标**：只有在首要风险没有变差的策略之间，才最大化截止日前获得可行住房的概率。
4. **第三目标**：再比较找房时间、总现金占用、通勤成本和沟通摩擦。更快、更便宜或更好玩都不能抵消安全退步。
5. **产品北极星**：使用后能识别关键风险并完成正确现实核验的用户比例；游戏时长、注册量和成交率是诊断指标，不是最终目标。

形式化定义、假设和不可宣称边界见 [`docs/model/OBJECTIVE_FUNCTION_V0.md`](./model/OBJECTIVE_FUNCTION_V0.md)。

## #4: 用现有数据能否先做历史回放？

Blocked by: #3  
Type: Research

### Question

9,935 条首批快照能支持哪些结论，哪些只能做结构测试？

### Answer

已解决（2026-09-03），结论为 **市场状态回放部分成功，安全目标验证仍被阻塞**。

1. 原有 RTMS 每区最新 100 条样本被 manifest 正确拒绝用于统计推断；跨期汇总也缺少时间切片。
2. 新增首尔市 2022–2024 年官方租赁年度文件，1,628,479 条原始行经合同年/受理年隔离、无效行拒绝和最小单元格抑制后形成 7,125 条月度聚合记录。
3. 完成 2022→2023、2023→2024 两折“上一年同月同组中位数”回放。它是基于最终年度文件的回顾性重建；受理年过滤去除了已知跨年泄漏，但不能还原历史截止日当时的文件版本。
4. 2025 官方文件因 41.13% 逐字段完全重复且无可靠唯一键而隔离，未擅自去重。
5. 结果证明真实价格带可以驱动 v0 状态和情景，但不能证明实时空房、个体合同安全、押金损失或外国人找房时长；具体误差以链接报告中的最终重跑结果为准。

资产：[`历史回放报告`](./research/historical-replay-baseline.md)、[`机器结果`](./research/historical-replay-results.json)、[`新增数据快照`](../data/snapshots/2026-09-03/seoul-rental-history/manifest.json)。

## #5: 最小可运行模型怎么做？

Blocked by: #4
Type: Prototype

### Question

能否在全部数据到齐前，用规则 + 蒙特卡洛与综合情景变量跑通一个可复现的沙盒？

### Answer

已解决（2026-09-03）。实现了固定 seed 的规则 + 蒙特卡洛最小世界模型，公开 seam 只有“单情景运行”和“情景矩阵运行”两个纯函数；CLI 负责校验快照并绑定输入哈希。

1. 真实输入只使用 2024-08 首尔区/月/住宅类型/租赁类型聚合分位带，并标为 `observed`；租客档案与核验状态标为 `synthetic`；未校准政策参数及其派生量标为 `modeled`。
2. 合成抽样只对历史分位带做分段线性插值/外推，用来施加预算压力，不生成房源，也不估计真实押金损失或合同伤害概率。
3. 机制门槛分别检查市场价格压力代理、四项强制现实核验和有界临时住房退路。由于没有 `R_D`、`R_C` 与 `P(H)` 标签，完整 `safetyGate` 永远返回 unknown，不能被代理门槛冒充。缺证据时不会输出签约；冲突会升级给持牌专业人员；无时间且无可负担退路时明确返回无安全路径。
4. 9 个“区 × 预算 × 入住周 + 冲突探针”情景固定为每情景 5,000 次抽样。结果覆盖 2 次预算/市场调整、4 次临时住房并继续核验、1 次专业升级和 2 次进入人工合同复核。
5. 相同市场单元格共享随机流，使预算反事实使用相同抽样；场景排序不影响结果。情景字段采用严格白名单；CLI 从通过校验的 manifest 传播来源标签，并同时绑定数据文件、manifest、情景和模型代码哈希。当前测试只证明可重复性、输入拒绝、安全优先和单调性。

资产：[`模型说明`](./model/MINIMUM_WORLD_MODEL_V0.md)、[`情景矩阵`](./model/MINIMUM_WORLD_MODEL_SCENARIOS_V0.json)、[`机器结果`](./model/MINIMUM_WORLD_MODEL_RUN_V0.json)、[`纯函数核心`](../worldmodel_data/model_v0.py)。

## #10: 产品视觉如何讲清“事实—推演—演练”？

Blocked by: #5, #8  
Type: Prototype

### Question

怎样让用户一眼看懂哪些是真实数据、哪些是概率、哪些是游戏情境？

### Answer

待解决。推荐三层视觉语法：

- **Explore / 事实层**：地图和时间戳，只展示 observed。
- **Simulate / 推演层**：一个月时间线、区间对比、置信区间和参数开关，展示 modeled。
- **Rehearse / 游戏层**：第一人称场景、可选行动与局后复盘，综合 observed/modeled/synthetic，逐项标签。

不使用一个不可解释的红色“区域危险分”，不用 3D 城市装饰冒充模型能力。

## #13: 能否发论文？

Blocked by: #4, #6, #9  
Type: Research

### Question

什么研究贡献足以超过“做了一个产品”？

### Answer

待解决。优先级：

1. **HCI / serious game**：决策演练是否显著提高外国租客的风险识别与行动选择。

仅用公开数据生成六格卡不足以成为强论文；需要明确新问题、基线、实验和可复现证据。
