# 外国租客决策世界模型：目标函数 v0

## Target

把“优先更少承担押金及合同风险”写成一个可编码、可回放、可证伪的决策目标，并防止找房速度、成交率、通勤便利或游戏参与度抵消安全退步。

## Status

**COHERENT AFTER REFRAMING / EXTRA ASSUMPTION**

原先的“硬约束内加权多个目标”需要改成分层优化。若把安全、速度和便利放进同一个加权总分，足够大的速度收益可能数学上抵消押金或合同风险，这与产品原则冲突。v0 因此采用“安全门槛 → 安全风险 → 获得住房概率 → 便利成本”的词典序。

## Invariant Object

模型始终优化 **外国租客在一次找房旅程中可避免的押金与合同伤害**，而不是某套房的“好坏分”、成交率或游戏得分。

这个对象跨三种界面保持不变：租前区域速览展示风险来源，世界模型比较行动后果，Game Only 让用户练习相同的核验与选择。

## Assumptions

1. 用户给出预算、最大可承受押金暴露、入住截止日、通勤容忍度，以及临时住房的最长时间与最高成本。
2. 一部分状态来自真实且带时间戳的数据；缺失状态必须标记为 `modeled` 或 `synthetic`。
3. 押金损失可以用金额或占用户可承受损失上限的比例表达。
4. 合同伤害在 v0 中是“关键证据缺失、条款矛盾、签约/付款权限未核验、保护路径未确认”等可观察代理变量，不是对合同效力的法律裁判。
5. 模型允许“不签、暂停、进一步核验、寻求专业帮助或先住临时住房”，因此无安全可行房源时不必强行推荐。
6. 风险阈值、严重度和尾部概率参数在拥有真人结果数据前是政策参数，必须做敏感性分析，不能伪装成经验真值。

## Notation

- `x`：租客档案与约束。
- `h_t`：截至步骤 `t` 的观察、选择和证据历史。
- `a_t`：下一行动，如查看证据、咨询、预约、签约、放弃或临时住宿。
- `π(a_t | h_t, x)`：根据当前信息选择行动的策略。
- `Y`：该策略在一个完整情境中的终局结果。
- `L_D(Y) ≥ 0`：押金相关的可避免财务损失。
- `L_C(Y) ∈ [0, 1]`：合同相关可避免伤害的严重度代理值。
- `B_D(x) > 0`：用户声明的最大可承受押金损失。
- `R_D(π, x)`、`R_C(π, x)`：押金和合同伤害的尾部风险。
- `H(Y) ∈ {0, 1}`：在固定评估期内是否持续有满足现金约束的住处；评估期必须长于用户允许的临时住宿上限。
- `V(Y) ∈ {0, 1}`：截止日前是否获得满足约束的非临时可行住房结果。
- `p_min(x)`：为避免“永远不签约”这一退化答案，策略至少要达到的住房连续性概率。
- `C(Y)`：时间、现金占用、通勤和沟通摩擦组成的次级成本。

## Derivation Strategy

先定义哪些行动根本不能由模型直接推荐，再分别限制押金风险与合同风险。只在同时通过两项风险门槛的策略中比较住房成功率，并仅在安全与住房结果近似相同的策略之间比较便利成本。

这种构造有两个目的：避免不同单位的风险被随意相加，也避免高参与度或快速成交掩盖小概率但灾难性的损失。

## Derivation Map

`租客约束 x + 当前证据 h_t`

→ `安全门槛 G(π, x)`

→ `分别估计押金尾部风险 R_D 与合同尾部风险 R_C`

→ `筛出安全可行策略 Π_safe(x)`

→ `最小化两类安全风险的最坏相对占用`

→ `在安全不退步的集合内最大化 P(V = 1)`

→ `最后最小化时间/现金占用/通勤/沟通成本 C`

## Main Derivation

### 1. 行动级安全门槛

定义 `G(π, x) = 1` 表示策略满足以下条件：

- 不要求用户投入超过其现金预算；
- 不让用户在没有可接受退路时越过入住截止日，且临时方案不得超过用户设定的时间和成本上限；
- 达到最低住房连续性要求 `P(H(Y) = 1 | x, π) ≥ p_min(x)`，避免把“什么都不做”或“无限住临时房”误判为最佳策略；
- 在付款或签约前，不跳过适用于该情境的权属/权限、权利负担、押金保护可行性和关键合同条款核验；
- 证据不足或相互矛盾时，行动只能是补充核验、升级到专业人员、退出或采用临时方案。

这是一项产品政策定义，不是从数据推导出的定理。

### 2. 分离两类尾部风险

对给定策略，定义：

```text
R_D(π, x) = CVaR_α(L_D(Y) / B_D(x) | x, π)
R_C(π, x) = CVaR_α(L_C(Y) | x, π)
```

`CVaR_α` 表示最坏 `1-α` 比例结果中的平均损失。使用尾部风险而非只看平均损失，是为了不让“多数时候没事”掩盖少量灾难性押金事件。

给定可审计阈值 `τ_D` 与 `τ_C`，安全可行策略集合定义为：

```text
Π_safe(x) = { π : G(π, x) = 1,
                  P(H(Y) = 1 | x, π) ≥ p_min(x),
                  R_D(π, x) ≤ τ_D,
                  R_C(π, x) ≤ τ_C }
```

如果 `Π_safe(x)` 为空，模型必须返回“当前约束下没有足够证据支持安全推进”，并给出下一项现实核验、需要调整的明确约束或有界临时方案；它不能为了生成推荐而暗中放宽阈值。

### 3. 首要目标：最小化安全风险

在安全可行集合内，先求：

```text
r(π, x) = max(R_D(π, x) / τ_D,
              R_C(π, x) / τ_C)

r*(x) = min_{π ∈ Π_safe(x)} r(π, x)
```

这里的 `max` 使押金与合同风险不能互相抵消。它不表示两项风险在法律或经济上完全等价，只表示产品不接受任何一项逼近上限却被另一项低风险掩盖。

允许一个透明的小容差 `ε_r`，得到安全近优集合：

```text
Π_r(x) = { π ∈ Π_safe(x) : r(π, x) ≤ r*(x) + ε_r }
```

### 4. 次要目标：提高获得可行住房的概率

只在 `Π_r(x)` 中比较：

```text
p*(x) = max_{π ∈ Π_r(x)} P(V(Y) = 1 | x, π)
```

再以透明容差 `ε_p` 保留：

```text
Π_v(x) = { π ∈ Π_r(x) :
           P(V(Y) = 1 | x, π) ≥ p*(x) - ε_p }
```

因此，更快获得住房只有在押金和合同风险没有实质变差时才有资格成为优势。

### 5. 第三目标：降低便利成本

最终策略为：

```text
π*(x) ∈ argmin_{π ∈ Π_v(x)} E[C(Y) | x, π]
```

`C` 可以拆成找房天数、落地现金占用、通勤负担和沟通步骤。各项权重可以个性化，但它们只影响第三层排序，不能跨层补偿安全或住房可行性。

## Remarks and Interpretation

- **对产品**：区域速览不输出单一“危险分”，而是展示影响 `R_D`、`R_C` 的证据、缺口和必须完成的现实核验。
- **对游戏**：高分来自在压力下守住安全门槛、识别缺失证据并选择正确核验，不来自最快签约。强行推进不安全合同应直接触发复盘，而不是用其他奖励抵消。
- **对历史回放**：现有数据可以先测试输入编译、阈值单调性和极端场景；没有真人合同与押金结果标签时，不能估计真实的 `R_D`、`R_C` 校准度。
- **对论文**：可检验假设应是“安全优先的决策演练是否改善风险识别、核验行为或结果”，而不是“模型会预测哪套房安全”。
- **对商业**：成交率不是优化目标，但经用户同意收集的核验行为和最终结果可以形成校准数据闭环。

## Boundaries and Non-Claims

1. v0 不判断某套房或某份合同“合法”“安全”或“值得签”。
2. v0 不替代韩国律师、持牌中介、担保机构、登记文件、现场检查或政府机关。
3. `L_C` 是决策支持代理量，不是法律结论；其规则上线前必须由韩国相关专业人员审阅。
4. 公开数据只能支持其时间、空间和许可范围内的陈述，不能证明实时空房或个体房源状态。
5. 在真实结果数据不足时，概率值只用于沙盒与敏感性测试，界面必须标为 `modeled` 或 `synthetic`。
6. 目标函数降低的是可避免风险暴露，不保证用户不会遭受损失。

## Open Risks

1. `τ_D`、`τ_C`、`α`、`ε_r` 和 `ε_p` 尚未通过用户研究、专业审查和真实结果校准。
2. 合同代理变量可能漏掉少见但严重的制度风险，也可能对证据不足的正常交易过度保守。
3. 若临时住房不可得或成本过高，“拒绝不安全交易”可能转化为无处居住风险，必须将住房连续性作为安全门槛的一部分。
4. `p_min` 太高会使模型无解，太低又会放大“保持观望”的退化策略，需要通过情境测试和用户研究确定。
5. 用户自报的可承受损失可能受信息不足影响，需要用解释和默认上限防止误设。
6. 不同签证、住房类型、地区与合同结构可能需要不同检查点，v0 不能直接泛化到所有外国租客。
7. 数据缺失若与外国人被拒、语言障碍或非正式交易相关，模型可能系统性低估真实摩擦。
